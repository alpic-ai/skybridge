`defineServer` declares your MCP behavior: setup, [tools](/build/tools), resources, prompts, and native middleware. `Skybridge` hosts that definition on an [Express](https://expressjs.com/)-backed HTTP server at `/mcp`, with OAuth and custom routes. Pass the same definition to [evals](/test/evals).

## Example

The app registers one tool and exports its type for the typed client hooks. A separate entry file runs it.

<CodeGroup>
```ts src/server.ts
import { defineServer, Skybridge } from "skybridge/server";

export const service = defineServer({
  name: "shop",
  version: "1.0",
  handler: (server) => server.registerTool(/* ... */),
});

export const app = new Skybridge({ server: service });
export type AppType = typeof service;
```

```ts src/index.ts
import { app } from "./server.js";

export default await app.run();
```
</CodeGroup>

Keeping the definition in `server.ts` and the `run()` call in `index.ts` lets tests and [evals](/test/evals) import it without starting a server.

## `defineServer`

```ts
defineServer({ setup?, dispose?, handler, name?, version?, ...serverOptions });
```

Returns a reusable `ServerDefinition`, not a connected SDK server. Its tool types flow through composition, `Skybridge`, `start`, and `generateHelpers`. Implementation metadata and SDK server options belong here; omitted `name` and `version` default to `skybridge` and the framework version.

### Immutable middleware composition

```ts
const logged = service.mcpMiddleware("tools/call", async (request, _extra, next) => {
  console.log(request.params.name);
  return next();
});
```

This creates a new definition without changing `service`. It accepts the same filters as [`McpServer.mcpMiddleware`](/api-reference/mcp-server#mcpmiddleware). Each newly composed wrapper runs before the existing pipeline on requests and after it on responses, including middleware registered inside `handler`.

### Execution lifecycle

```ts
const execution = service.createExecution();
try {
  const instance = await execution.createServerInstance();
  await instance.connect(transport);
  // Keep the execution open for the transport's lifetime.
} finally {
  await execution.close();
}
```

An execution owns its setup result and SDK instances. `setup` runs once per execution; `createServerInstance` registers a fresh server each time. `close` closes remaining instances and invokes `dispose(config)` once. A `Skybridge` host owns one execution; every eval conversation owns another. Put mutable state in `setup` to isolate conversations and production.

`createExecution({ toolImplementations })` optionally supplies typed terminal tool replacements returning MCP tool results. They run after normal input validation and per-tool authorization, inside application middleware. Returning `undefined` uses the original implementation. Evals expose this through [`stubs`](/test/evals#stubs).

## Constructor

```ts
new Skybridge(config: SkybridgeConfig);
```

Pass a definition and HTTP options. An `oauth` function receives the host execution's setup result.

```ts
type SkybridgeConfig = {
    server: ServerDefinition;
    oauth?: OAuthConfig | OAuthProvider | ((config: Config) => OAuthConfig | OAuthProvider);
    json?: JsonOptions;
};
```

The existing `new Skybridge({ name, version, setup, handler, oauth, ... })` constructor remains supported. It adapts those declarations into `app.server` and uses the same execution implementation.

### `name`, `version`

The MCP implementation info (`name`, `version`, and optionally `title`, `description`, `icons`, `websiteUrl`). SDK `ServerOptions` such as `instructions` or `capabilities` are forwarded when you set them; registering tools and views advertises those capabilities for you.

`icons` is the app's icon, a standard MCP field. Hosts choose whether and where to show it. Tools can carry their own [`icons`](/api-reference/register-tool#icons) too.

### `handler`

The definition's handler receives a fresh [`McpServer`](/api-reference/mcp-server) and must **return** that server's chain of registrations. The return value carries your tool types into `typeof service`.

The handler runs for **every request**, so keep it to registration. Anything else in its body (a connection pool, a timer, a file read) runs per request too: move it into [`setup`](#setup), whose result is the handler's second argument. Skybridge warns once in the console when a handler takes more than 50ms. The handler must stay synchronous.

### `setup`

Loads what the execution needs: a connection pool, a client, remote config, secrets. It runs **once per execution**, never when the module is imported. Its awaited result is passed to `handler` and to the host's `oauth` function. Release those dependencies in `dispose(config)`; hosts and evals also clean up after startup fails once setup has completed.

```ts src/server.ts
export const service = defineServer({
  name: "shop",
  version: "1.0",
  setup: async () => loadConfig(),
  handler: (server, config) => server.registerTool(/* reads config */),
});
export const app = new Skybridge({
  server: service,
  oauth: (config) => descopeProvider({ url: config.mcpServerUrl }),
});
```

### `oauth`

An [identity provider](/guides/auth-providers) (`oauth: workosProvider({ ... })`), a raw [`OAuthConfig`](/api-reference/custom-provider#returns), or a function of the `setup` result returning either. Providers defer discovery: nothing runs at module import, the network call happens once at `run()`. When set, it mounts the well-known OAuth metadata and bearer-token verification on `/mcp`.

The config also carries the claim shape its verifier produces, so handlers read `extra.http.authInfo.extra` typed, with no declaration of their own. See [Type the Claims You Read](/build/auth#type-the-claims-you-read).

### `json`

Options for the [`express.json()`](https://expressjs.com/en/5x/api/express/#expressjsonoptions) parser Skybridge pre-applies, for example to raise the default 100kb body-size limit.

### `skills`

Set to `true` to serve [Agent Skills over MCP](/guides/skills) from `src/skills` and declare the `io.modelcontextprotocol/skills` capability.

<Info>
Skills over MCP tracks [SEP-2640](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2640), which is still under review. The feature is **experimental** and may change with the spec.
</Info>

## Properties

### `server`

The reusable server definition hosted by this app. Evals may pass it directly as `start({ server: app.server, model })`; `start({ app, model })` remains a compatibility shorthand.

### `express`

The underlying Express app, for custom routes, middleware, and settings. Register handlers before `run()`.

<Info>
[Alpic Cloud](https://alpic.ai/solutions/cloud) routes traffic only to `/mcp`. Custom routes work locally and on self-hosted deployments.
</Info>

## Methods

`use` and `useOnError` return the app, so calls chain.

### `use`

```ts
app.use(...handlers: RequestHandler[]): this;
app.use(path: string, ...handlers: RequestHandler[]): this;
```

Registers [Express middleware](https://expressjs.com/en/guide/using-middleware/) on the underlying app, optionally scoped to a path. Mirrors `app.use`.

### `useOnError`

```ts
app.useOnError(...handlers: ErrorRequestHandler[]): this;
app.useOnError(path: string, ...handlers: ErrorRequestHandler[]): this;
```

Registers an [Express error handler](https://expressjs.com/en/guide/error-handling.html), optionally path-scoped, to run after the `/mcp` route. A default handler runs last, responding with a 500 [JSON-RPC](https://www.jsonrpc.org/) error when nothing else has sent a response.

### `run`

```ts
app.run(): Promise<{ fetch: (...args: unknown[]) => unknown } | Express | undefined>;
```

Resolves `setup` and `oauth`, applies your middleware, mounts `/mcp`, and listens (default port `3000`). On serverless platforms, export what it returns so the platform can route requests to it. See [Deploy](/ship/deploy) for the per-platform setup.

### `connect`

```ts
app.connect(transport: Transport): Promise<void>;
```

Connects the app to a transport you manage, such as stdio for a desktop host. For HTTP, `run()` sets the transport up for you.

### `createServerInstance`

```ts
app.createServerInstance(): Promise<Server>;
```

Builds a fresh MCP server after the host's `setup` and `oauth` resolve. Middleware is assembled from the definition and its registrations before the instance is returned. For eval-only wrappers, derive a definition with `service.mcpMiddleware(...)` and pass it to `start`.

```ts
const instance = await app.createServerInstance();
await instance.connect(transport);
```

### `close`

```ts
await app.close();
```

Closes the HTTP handler, listener, and owned execution, including `dispose`. Repeated calls share the same cleanup. A failed `run()` also closes these resources.
