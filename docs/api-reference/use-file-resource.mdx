A [file entrypoint](/api-reference/register-tool#openai) opens your view on a file the user picked in ChatGPT desktop. The view never gets the file's path: the tool input carries an opaque `file.resourceUri` instead. `useFileResource` reads that resource, re-reads it whenever the host reports a change, and saves edits back.

<Info>
Reading uses the standard MCP `resources/read`. Text or blob selection and writes come from the [OpenAI MCP extensions](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md), so only **ChatGPT** desktop supports them.
</Info>

## Example

A part editor loads the opened file as text and saves the user's edits.

```tsx
import { useState } from "react";
import { useFileResource } from "skybridge/web";
import { useToolInfo } from "../helpers.js";

function PartEditor() {
  const { input } = useToolInfo<"open-part">();
  const { data, isLoading, write } = useFileResource(input.file?.resourceUri, {
    representation: "text",
  });
  const [draft, setDraft] = useState<string>();

  if (isLoading || !data || !("text" in data)) {
    return null;
  }
  const save = async () => {
    const result = await write({ text: draft ?? data.text });
    if (result.outcome === "conflict") {
      alert("The file changed on disk. Reload it before saving.");
    }
  };
  return (
    <>
      <textarea value={draft ?? data.text} onChange={(e) => setDraft(e.target.value)} />
      <button disabled={!data.writable} onClick={save}>Save</button>
    </>
  );
}
```

## Parameters

### `uri`

```tsx
uri: string | undefined;
```

The resource to read, usually `file.resourceUri` from the tool input. Pass `undefined` to do nothing, for example when the view also opens outside a file entrypoint.

### `options`

```tsx
options?: { representation?: "text" | "blob" };
```

Asks ChatGPT to return the contents as text or as a base64 blob. Without it, ChatGPT picks one, so handle both.

## Returns

### `data`

```tsx
data: ({ text: string } | { blob: string }) & {
  mimeType?: string;
  writable: boolean;
  etag?: string;
} | undefined;
```

The current contents. `writable` tells whether ChatGPT accepts writes, and `etag` identifies this version. `undefined` until the first read completes.

### `isLoading`, `error`

`isLoading` is `true` while a read is in flight, including the re-reads after a change. `error` holds the last read failure.

### `write`

```tsx
write: (content: { text: string } | { blob: string }) =>
  Promise<
    | { outcome: "saved"; etag: string }
    | { outcome: "conflict"; etag: string }
    | { outcome: "too-large"; maxBytes: number }
  >;
```

Saves new contents through `openai/resources/write`, with the current `etag` as `ifMatch`. When the file changed since the last read, ChatGPT answers `conflict` instead of overwriting it. On `saved`, `data` takes the new contents and etag. It rejects with a `NotSupportedError` when the host doesn't advertise `openai/resource` or `data.writable` is `false`.
